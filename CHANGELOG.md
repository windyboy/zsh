# Changelog

## v5.5.0

- Hardened the installer/update scripts: `update.sh` now re-execs its updated copy when a pull changes the script itself (bash reads scripts by byte offset, so continuing mid-file risks garbled execution); the config snapshot excludes `.git` and `backup/` is gitignored (snapshots previously duplicated the whole repository history and polluted `git status`); a missing zinit is now a skip instead of a hard failure — a default install (plugins off) used to make every `./update.sh` exit 1; `install.sh` no longer crashes on a dangling `~/.zshenv` symlink (`-e` misses it; `ln -s` then fails with "File exists" under `set -e`, bypassing consent/`--force`); oh-my-posh install failures clean up their temp file; backup cleanup globs instead of `find | sort | tail` (space-safe, only timestamp dirs).
- Environment fixes: `EDITOR` falls back `code` → `vi` by `command -v` detection (`code` never exists on typical Linux/SSH hosts); `LC_ALL` is no longer defaulted (it overrides `LANG` and every `LC_*` category, and minimal systems warn `setlocale` without the en_US.UTF-8 locale); `reload`/`zreload` reset `ZSH_MODULES_LOADED` so the array no longer doubles per reload, and completion's `fpath` entries dedup on re-source; `validate` counts functions with `${#functions}` — `declare -F | wc -l` is bash syntax and always counted 0 in zsh; user bin dirs prepend so `~/.local/bin` ends up highest priority; `NVM_DIR` prefers the official `~/.nvm` when present; `list-colors` only applies `LS_COLORS` when it is actually exported.
- Docs match reality again: REFERENCE.md lists the `update` test group and `perf --startup`, states the real load order (`local.zsh` is followed by the per-host file, not last), and documents every `ZSH_*` toggle (`ZSH_DISABLE_POSH`/`ZSH_ENABLE_POSH`/`ZSH_OMP_TRANSIENT`/`ZSH_PROFILE`/`ZSH_DEBUG`/`ZSH_MAX_*`/`ZSH_UPDATE_SELF_SKIP`) in a table; `env/README.md` recommends `reload` instead of claiming all modules are idempotent; `version()` lists the restored `env` module; the phantom `custom/` directory (nothing ever loaded it) and its comment were removed.
- Test/Makefile honesty: `log_fail` now prints which assertion fired (a bare "FAILED" hid the cause); the machine-specific test no longer fails when the moved `bin/env` hack was later deleted from a local override (repo invariant is `zshrc` cleanliness, not local file content); `make lint` fails on real ShellCheck findings (was `|| true`); `make all` no longer runs the update group twice; `make zsh-syntax` tolerates empty globs, covers `modules/lib/`, and is `.PHONY`.
- Fixed typed characters smearing on Ubuntu/SSH (`ls` → `lls`): zshenv no longer forces `COLORTERM=truecolor`, Oh My Posh is skipped over SSH unless the client identifies a capable emulator (`TERM_PROGRAM` / Kitty / WezTerm / Windows Terminal / iTerm), and `OMP_TRANSIENT` defaults off. Set `ZSH_DISABLE_POSH=1` or `ZSH_ENABLE_POSH=1` to override.
- Fixed a hanging interactive startup: `forge zsh plugin`/`forge zsh theme` (which can stall indefinitely on a dead backend call) are now timeout-guarded with a 60-minute failure marker, so fresh shells skip them instead of blocking (W1N-221).
- Fixed `go` being broken in shells: a stale pinned `GOROOT` (`/usr/local/Cellar/go/1.26.7/…`) failed after a Homebrew upgrade to 1.27.0 (`cannot find GOROOT directory`); the export was removed — go auto-detects its root (W1N-222).
- PATH entries no longer accumulate duplicates in nested shells: `modules/env.zsh` is back in the module list and owns PATH policy (`add_to_path` with existence + duplicate guards, `path-status`/`path-clean`), and the machine override uses `add_to_path` instead of naively re-wrapping `$PATH`.
- bun completions now resolve on macOS: `${BUN_INSTALL:-$HOME/.bun}/_bun` (the hardcoded `/home/windy/.bun/_bun` never matched on this machine).
- Env layering is documented and enforced: `env/local/environment.env` holds machine `export`s + feature toggles and is sourced pre-module (so `ZSH_ENABLE_PLUGINS` is set before `plugins.zsh` reads it — plugins were silently off in fresh login shells); `env/local/hosts/<hostname>.env` holds per-host PATH additions via `add_to_path` and is sourced post-module. The env template was de-personalized (everything is a commented example; no author-specific values).
- `install.sh` finalizes with simpler guidance (the detailed next steps now live in `env/README.md`); the redundant inline NVM lazy-loader and the hardcoded `BW_SESSION` token guidance were removed.
- `test.sh`'s per-host test uses a synthetic hostname so it can never overwrite or delete a real `env/local/hosts/<host>.env` (it previously deleted `MacBook-Pro.local.env`); `.zsh_sessions/` is gitignored.

## v5.4.0

- Fixed a flaky/hanging shell startup: the dump-rebuild path called plain `compinit`, whose compaudit prompt (triggered whenever any fpath entry has a world-writable parent, e.g. a cache dir under `/tmp`) was silenced by `2>/dev/null` yet still blocked on stdin — appearing as a frozen shell — and, on abort/EOF, compinit unfunctions itself and compdef, surfacing as the misleading `command not found: compinit`. The rebuild now uses `compinit -u -d` (never prompts); a contract test guards it.
- Hygiene cleanup: removed dead counters (`loaded_modules`/`total_modules`) in zshrc and unset loop/host temp variables (top-level `local` leaks into the global namespace); deleted the unused `ZSH_CACHE_TTL`; deleted the `config_sync` TODO placeholder; deleted the empty `path` module and its `path-reload` alias (re-sourcing it re-appended to `ZSH_MODULES_LOADED`); the startup banner is now opt-in via `ZSH_PROFILE=1` instead of writing to stderr on every interactive shell; `zconf` and the Alt+E binding honor `$EDITOR` instead of hardcoding `code`; made `colors.zsh` idempotent (completion/plugins/utils all source it, tripling its `ZSH_MODULES_LOADED` entry); deleted the never-validated `release.sh` (zero tags existed) — releases are now documented as manual annotated tags in README.
- Aligned docs and hints with reality: the three "reload with `source ~/.zshrc`" hints now point at `zreload` (ZDOTDIR redirection makes `~/.zshrc` a no-op); `version()` lists the real module set (it claimed a non-existent `security` module and omitted `colors`/`path`); the zshrc comment no longer claims zshenv uses read-only `typeset -grx` (it is `-gx`); `install.sh` now enforces the README's Zsh 5.8+ requirement at install time via `is-at-least`; the unimplemented `update.sh --force` placeholder was removed, and unknown/mistyped options (e.g. `--skip-bakcup`) are now rejected with rc=1 instead of being silently ignored.
- Hardened `update.sh`: `update_oh_my_posh` now prefers brew when it owns the installation, otherwise updates the existing binary in place (resolving symlinks; sudo only when the target directory is not user-writable — previously it always installed a second copy to `/usr/local/bin`), and verifies the release's SHA256 `checksums.txt` before installing anything (previously an unverified binary was sudo-installed). `update_zinit`'s not-found error now points at the real installation mechanism (first interactive shell with `ZSH_ENABLE_PLUGINS=1`) instead of install.sh, which never installed zinit. `BACKUP_DIR` and the backup cleanup root now derive from `$ZSH_CONFIG_DIR`, and `path-reload` no longer hardcodes `~/.config/zsh`.
- Made the plugin system honest: `plugins/core.list` is now the real registry — `modules/plugins.zsh` parses it at load time (`zinit light` for owner/repo entries, `zinit snippet` for OMZP::/OMZL::, preserving the previous wait"0"/wait"1" turbo behavior) instead of loading a hardcoded array. The registry was aligned with reality (dropped the never-loaded `le0me55i/zsh-extract` and `rupa/z`, added the actually-loaded `OMZP::extract`), the empty `plugins/optional.list` was deleted, and the undocumented `ZSH_ENABLE_PLUGINS` switch (plugins were silently off by default) is now documented in README/REFERENCE, mentioned by the installer, and the phantom `ZSH_ENABLE_OPTIONAL_PLUGINS` variable was removed from REFERENCE.md and the env template.
- Stopped overriding `TERM` in `zshenv` (unconditional `xterm-256color` broke tmux/kitty/SSH terminal declarations); the terminal emulator's own TERM is now respected.
- Fixed five runtime bugs: `safe_rm`'s ownership check now uses zstat's `uid` element compared against `$EUID` (the previous `+owner` element does not exist, silently disabling the check); the `ls` alias now branches by platform (`-G` on macOS, `--color=auto` on GNU — where `-G` means `--no-group`); `rmempty` uses `sed -i.bak` + cleanup so it works with both GNU and BSD sed; the fzf-tab conflict detection was removed (zinit turbo-loads the plugin after completion.zsh runs, so the check could never see it) and the standard completion styles now apply unconditionally; `perf --startup` is implemented (three timed interactive spawns), the unimplemented `--history` was removed, and `perf`'s long options actually parse now — the zparseopts specs lacked the leading dash, so `--modules`/`--memory`/`--startup` were all silently ignored and unknown options/typos passed without error (now `-F` reports them and any leftover argument fails with rc=2).
- Hardened the test suite itself: syntax checks now run per file (`zsh -n a b` only parses `a`, so `zshenv` and three of the four shell scripts were never actually checked), `test_modules` verifies zshrc's `module_list` against `modules/` in both directions (the hardcoded list missed `path`/`utils`) plus asserts zstat's `uid` element reports the caller EUID, the installer-contract sandbox runs in a subshell so install.sh's `set -euo pipefail` can no longer leak into the test runner, and the `update` group is now listed in the usage text, AGENTS.md, and README.
- Made CI honest: the test-suite step now fails the build on any test failure (previously it logged and continued), the machine-specific env assertions skip gracefully when `env/local/environment.env` is absent, dead steps probing non-existent scripts and the hardcoded all-PASSED test report were removed, ShellCheck covers `test.sh` again, and the trufflehog scan uses full history (`fetch-depth: 0`), valid flags, and no longer continues on error. `.trufflehogignore` was deleted (no tool consumes it).
- Moved machine-local state out of the tracked tree: `.zsh_history`, `themes/prompt.zsh.backup`, and `themes/theme-preference` are no longer tracked; the theme preference now lives at `$ZSH_CACHE_DIR/theme-preference` (with a one-time migration from the old in-repo path), and `in-memoria.db*` / `plans/` are gitignored. Keeps `update.sh`'s `git pull --ff-only` self-update working after `posh_theme` writes the preference.

- Unified the zinit directory path across `update.sh`, `validation.zsh`, and the runtime (`ZINIT_HOME`), fixing the stale `…/zsh/zinit` path.
- Added framework self-update to `update.sh` (`git pull --ff-only`) with `--skip-self` / `ZSH_UPDATE_SELF_SKIP=1` opt-out.
- Added `set -euo pipefail` to `update.sh` so failures surface instead of being silently swallowed.
- Collapsed the dead `os`-branch in `update_oh_my_posh`.
- Replaced `update_zinit`'s hardcoded `origin/master` fetch/reset with a tracking-branch `pull --ff-only` (zinit's default branch moved to `main`).
- Moved the opencode PATH and `$HOME/.local/bin/env` hack out of the shared `zshrc` into the gitignored `env/local/environment.env`.
- Added `update` and machine-specific test groups covering the above.
- Aligned the repository with its supported lightweight workflow.
- Added `VERSION` as the canonical version source.
- Made the installer and test command contracts explicit.
- Removed obsolete `docs/history/` review and refactoring archives (Git history retains them).
- Dropped in-repo `TODO.md` in favor of Linear.
